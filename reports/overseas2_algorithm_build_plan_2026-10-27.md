# 해외2 4-ETF 리밸런싱 알고리즘 구축 계획안 (재작성)

- 작성일: 2026-10-27, Asia/Seoul. 정책 후보 v0.2 기준
- 입력 자료: [대화 이력](overseas2_algorithm_conversation_history_2026-10-26.md), [Pine 사용 설명서](quarterly_etf_pine_guide_2026-10-26.md), [PRD](../PRD.md)
- 범위: SCHD 25% · QQQM 25% · IEF 30% · IAUM 20%의 **분기 리밸런싱 검토 시점 안내**. 주문 실행·증권사 API·웹훅 주문은 범위 밖
- 성격: 정보 제공·의사결정 보조용 개발 계획. 수익이나 최대낙폭(MDD) 개선을 보장하지 않음

## 0. 한 줄 결론

**알고리즘의 뼈대(분기 점검 → ±5%p 이탈 확인 → 확정 주봉 추세로 해석 보조)는 유지하고, 다음 순서로 진행한다: ① 현금 정책 확정(✅ 2026-10-27 전액 포함) → ② TradingView 실행 검증 → ③ 과거 데이터로 정책 비교 → ④ 결과를 보고 파라미터와 조기 알림 여부 결정.** 지금까지는 "계산이 맞는지"만 확인했고, "실제로 돌아가는지"와 "이 방식이 효과가 있는지"는 아직 확인하지 못했다.

## 2. 먼저 정해야 할 것 (사용자 결정)

결정이 없어도 개발은 진행할 수 있지만, 아래 결정에 따라 **결과 화면과 백테스트 설계가 달라진다.**

| ID | 질문 | 선택지 | 기본 가정 (확정 전까지) | 영향 |
|---|---|---|---|---|
| D1 | 해외2 USD 현금(약 18%)을 어떻게 볼까? | ① 전액 투자 재원 ② 전액 별도 보유 ③ 일부만 투자 | **✅ 확정: ① 전액 투자 재원** (2026-10-27) | Pine 별도 보유 현금 = 0. 현금이 목표비중에 따라 네 ETF에 배분될 재원으로 계산됨 |
| D2 | 현금을 장기적으로 5번째 자산으로 둘 것인가? | 예 / 아니오 | **✅ 아니오** (D1 결정으로 정리됨) | 연구 범위는 PRD대로 네 ETF 100% |
| D3 | 낙폭은 원화 기준이 우선인가? | KRW / USD | KRW 1차, USD 2차 (PRD 가정) | 백테스트에 환율 데이터가 필요해짐 |
| D4 | 분기+5%p를 기본 정책으로 쓸 것인가? | 즉시 채택 / 비교 후 채택 | 비교 후 채택 (화면에는 후보로 표시) | Phase 3 결과로 3/5/7%p 중 결정 |

> **D1 결정의 영향 (2026-10-26 관측값 기준 산술 예시):** 현금을 포함하면 네 ETF가 모두 목표보다 부족하고, 가장 큰 이탈은 SCHD 약 −5.88%p로 허용폭을 넘는다. 즉 다음 분기 점검(2027년 1월 초 첫 5거래일)에서 비슷한 상태라면 `REBALANCE_REVIEW`가 뜨고, 내용은 **매도 없이 현금으로 네 종목의 부족분을 채우는 검토**가 된다. 그 전까지 화면에는 `DRIFT_WATCH`(이탈 관찰)가 표시될 수 있으며, 이는 즉시 매수하라는 뜻이 아니다. 실제 판단은 점검 시점 가격·수량으로 다시 계산한다.
>
> 이로써 PRD의 "네 ETF 100%" 연구 범위와 계정 운영 전제가 일치하게 되었다(PRD §10 갱신).

## 3. 알고리즘 설계 (v0.2 유지, v0.3에서 보완할 점 표시)

> **2026-10-27 지표 재선정 (승인·Pine v0.3 반영 완료, 테스트 22개 통과):** [재검토 보고서](tradingview_algorithm_reselection_2026-10-27.md)에서 인기 스크립트 15개를 다시 평가했다. 제안 내용은 추세 지표를 **SuperTrend 원조 지표판(84.3K) 하나**로 정리하고, 하락 중 보충 판단용으로 **CM_Williams_Vix_Fix(66K)**를 추가하며, Chandelier와 40주 SMA는 백테스트 비교군으로 돌리는 것이다. 아래 §3.2 해석표는 보고서 §5의 표로 바뀌었다. §3.4의 1·2번(현금 정책 표시, 알림의 정책·허용폭 표기)도 v0.3에 반영했다.

### 3.1 판단 흐름

```text
[입력] 수량 4개 · USD 현금 · 별도 보유 현금 · 확인 시각
   │
   ▼
① 데이터 점검 ── 실패 ──> DATA_CHECK (판단 보류)
   │ 통과: 네 ETF 같은 날 확정 종가, 입력 7일 이내, 주봉 14일 이내
   ▼
② 비중 계산
   투자대상 총액 = Σ(수량×전일 종가) + USD 현금 전액   (별도 보유 현금 = 0, 2026-10-27 확정)
   이탈(%p) = 현재비중 − 목표비중,  D = 네 종목 이탈의 절댓값 중 최대
   │
   ▼
③ 시점 판단
   ├─ 새 분기 첫 5거래일(또는 수동 점검) ── D ≥ 5%p ──> REBALANCE_REVIEW
   │                                     └─ D < 5%p ──> QUARTERLY_REVIEW
   └─ 분기 사이 ── D ≥ 5%p + 주봉 전환 ──> EARLY_REVIEW_CANDIDATE (표시만)
                └─ D ≥ 5%p            ──> DRIFT_WATCH
                └─ 그 외               ──> ON_TRACK
   │
   ▼
④ 종목별 해석 (REBALANCE_REVIEW일 때만 행동 문구 사용)
```

### 3.2 종목별 매수·매도 해석표

비중이 먼저이고, 추세는 **검토 순서와 분할 여부**에만 영향을 준다.

| 비중 | Chandelier · SuperTrend (확정 주봉) | 표시 | 의미 |
|---|---|---|---|
| 부족 | 둘 다 상승 | 보충 검토 우호 | 채우는 방향과 추세가 같음 (저점이라는 뜻은 아님) |
| 부족 | 둘 다 하락 | 분할·재확인 | 한 번에 채우지 않고 나눠서 검토 |
| 초과 | 둘 다 하락 | 축소 검토 우선 | 초과분 축소 목적과 추세가 같음 (전량 매도 아님) |
| 초과 | 둘 다 상승 | 초과분만 검토 | 상승 중이어도 쏠림 위험은 남음 |
| 어느 쪽이든 | 엇갈림 | 분할·재확인 | 두 지표를 합친 점수는 만들지 않음 |
| 어느 쪽이든 | 자료 부족 | 추세 미확인 | 비중 판단만 사용 |

### 3.3 파라미터 현황

| 파라미터 | 현재값 | 상태 | 확정 방법 |
|---|---|---|---|
| 허용폭 | 5%p | 후보 | Phase 3에서 3/5/7%p 비교 |
| 점검 창 | 새 분기 첫 5거래일 | 운영 기본값 | 실제 운용 2~3분기 후 조정 |
| Chandelier | 주봉 22 · ATR×3 · 종가 극값 | 원본 기본값 | Phase 2 원본 대조 → Phase 3 민감도 |
| SuperTrend | 주봉 10 · ATR×3 | 비교 표시 | Phase 3에서 Chandelier와 비교 |
| 추세 가격 계열 | 분할 조정 · 배당 미조정 | 임시 | 배당락이 추세를 흔드는지 Phase 3에서 비교 |

### 3.4 v0.3 보완 후보

1. **현금 정책 표시:** 화면과 알림에 "현금 전액 포함"을 표시하고, 별도 보유 현금에 0이 아닌 값이 들어가면 "확정 정책과 다름" 경고를 보여 준다.

## 5. Phase 3 정책 연구 설계

### 5.1 비교할 전략

| 코드 | 전략 | 역할 |
|---|---|---|
| S0 | 그대로 보유 (리밸런싱 없음) | 기준선 |
| S1 | 무조건 분기 복원 | 기준선 |
| S2 | 분기 + 허용폭 3 / 5 / 7%p | **현재 후보** |
| S3 | S2 + 추세 참고 분할 (하락 추세 종목은 절반만 먼저 실행) | 추세 효과 측정 |
| S4 | S2 + 분기 사이 조기 점검 (이탈 + 주봉 전환) | 조기 알림 승인 근거 |
| S5 | S3의 추세 지표 교체: SuperTrend / Chandelier / 40주 SMA | 어떤 추세 지표를 쓸지 결정 |
| S6 | S2 + Vix Fix 공포 구간에서 부족 종목 1차 분할 보충 | 공포 지표 효과 측정 |
| (선택) | 연간 복원 | Vanguard 자료의 대안 확인 |

### 5.2 데이터와 규칙

- **구간 분리:** 실제 4종목 공통 이력(QQQM·IAUM 출시 이후)과 장기 대체 이력(SCHD·QQQ·IEF·IAU)을 따로 계산하고 합치지 않는다.
- **원천:** 일별 가격, 분배금, 분할, USD/KRW 환율. 사용 권리를 확인할 수 있는 공급원을 Phase 0에서 고른다. TradingView 화면 데이터를 긁어 오는 방식은 쓰지 않는다.
- **저장·계산:** 작업공간 표준인 DuckDB + Polars를 쓴다. raw → normalized → derived 계층으로 나누고 출처와 산식 버전을 기록한다.
- **미래 정보 차단:** 신호는 확정 종가로 만들고, 체결은 **다음 거래일 가격 + 비용**으로 모의한다.
- **배당 이중 반영 금지:** 총수익 가격을 쓰거나, 배당 미조정 가격 + 분배금 재투자 중 한 가지만 쓴다.

### 5.3 비교 지표

KRW MDD(1차) · USD MDD · 롤링 12/36개월 MDD · 회복 기간 · CAGR · 회전율 · 거래 횟수 · 비용. 결과가 기준선보다 낫지 않으면 **현행 단순 정책(S2 또는 S1)을 유지하는 것이 정상 결론**이다.

## 6. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 별도 보유 현금 입력 실수 | 확정 정책(전액 포함)과 다른 비중으로 판단 | 입력값 0 유지, v0.3에서 0이 아니면 경고 |
| 현금 배분 후 현금 부족 | 배당·환전·수수료에 쓸 현금이 없음 | 결제 가능 현금과 비용을 주문 전 사람이 확인 |
| 수량·현금 입력 갱신 누락 | 잘못된 비중으로 판단 | 7일 한도, "변동 반영" 체크, 분기 점검 시 재확인 (구현됨) |
| 주봉 추세의 지연 | 이미 많이 떨어진 뒤 하락 표시 | 추세는 해석 보조로만 사용, 매매 명령으로 쓰지 않음 |
| 두 지표가 함께 틀림 | 같은 가격·ATR 기반이라 독립 증거가 아님 | 일치를 확신도로 쓰지 않음 (설계 반영됨) |
| 네 자산 동시 하락 | 리밸런싱으로 손실을 막을 수 없음 | 손절 장치가 아님을 문서와 화면에 명시 |
| 인기(Boost)를 성과로 오해 | 잘못된 기대 | Boost는 후보 선정 근거로만 기록 (설명서 §2) |
