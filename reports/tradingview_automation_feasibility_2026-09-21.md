# TradingView 알고리즘 적용 범위와 ETF 자동매매 가능성 검토

> **방향 변경(2026-09-21):** 이 문서는 과거의 기술적 가능성 검토 기록이다. 사용자의 현재 목표는 **주문 없는 MDD 우선 리밸런싱 타이밍 안내 시스템**이며, 구현 기준은 [새 개발 방향 문서](mdd_first_rebalancing_timing_advisor_2026-09-21.md)다. 실주문·승인형 주문·증권사 주문 API 설계는 현 범위에서 제외한다. 사용자는 티커를 SCHD·QQQM·IEF·IAUM으로 후속 확정했다.

- 기준일: 2026-09-21 (Asia/Seoul)
- 대상: 사용자가 제시한 1억 원, `SHCD` 25% / QQQM 25% / IEF 30% / `AUM` 20%, 주기적 리밸런싱
- 산출물 성격: 설계 검토. 프로그램·증권계좌·주문을 생성하거나 연결하지 않았다.
- 핵심 가정: `SHCD → SCHD`, `AUM → IAUM`. 두 티커는 사용자 확인 전 **미확정**이다. 목표비중·분기·±5%p도 사용자가 확정한 정책이 아니라 [선행 보고서](tradingview_all_weather_rebalancing_report_2026-09-21.md)의 **검증 대상 제안안**이다.
- 주의: 정보 제공 및 시스템 설계 목적이며, 수익 보장이나 개인별 매매 권유가 아니다.

## 1. 판단

**조건부로 구현 가능하다.** 네 ETF를 사고팔 수 있는 계좌, 해당 계좌에 허용된 해외주식 주문·잔고·체결 API, 인증수단, 환전·주문유형 규칙이 확인되면 분기 리밸런싱 자동화가 기술적으로 가능하다. 한국투자증권의 공식 API 목록에는 해외주식 주문·잔고·주문체결내역이 있고, IBKR에도 주문 및 포지션 API가 있다. 이는 **가능한 증권사 사례**이지 사용자의 계좌에서 바로 사용 가능하다는 뜻은 아니다. [KIS API 목록](https://apiportal.koreainvestment.com/apiservice-category), [KIS API 개요](https://apiportal.koreainvestment.com/apiservice-summary), [IBKR 주문 API](https://ibkrcampus.com/docs/web-api/v1/endpoints/orders/place-order)

추천 구현 순서는 `읽기 전용 계산·알림 → 사용자 승인 주문안 → 모의주문·섀도 운영 → 검증 후에만 실주문 자동화`다. 지금은 계좌·티커·실제 보유수량·비용·세무 조건이 확인되지 않았으므로 **실주문 자동화의 실행 적합성은 미확정**이다.

TradingView는 이 전략에서 **연구·가시화·보조 경보**에 가장 잘 맞는다. 네 자산의 실제 수량, 주문가능 현금, 환전 상태, 미체결, 부분체결의 진실은 증권사 계좌에 있다. 따라서 핵심 분기 리밸런싱은 독립적인 일정 실행기와 증권사 API가 계산해야 한다. TradingView의 `strategy.*` 주문은 우선 백테스트용 브로커 에뮬레이터의 주문이며, 이것만으로 실계좌 네 ETF가 자동 체결되지는 않는다. [TradingView 전략 알림 설명](https://www.tradingview.com/support/solutions/43000481368-strategy-alerts/), [Pine 전략 문서](https://www.tradingview.com/pine-script-docs/concepts/strategies/)

| 자동화 단계 | 할 수 있는 일 | 현 단계 판단 |
|---|---|---|
| 연구·감시 | TradingView 시뮬레이션, 주봉 추세 알림, 별도 계산기의 리밸런싱 필요 여부 표시 | 바로 설계 가능. 실제 시세·보유값 입력 전 결과는 가상값 |
| 승인형 주문 | 증권사 잔고를 읽어 주문안을 만들고 사용자 확인 후 전송 | 증권사 API·계좌 권한·티커 확인 후 개발 권고 |
| 완전 자동 주문 | 정해진 날 주문·취소·재시도·체결 확인·정산까지 수행 | 기술적으로 가능하지만 모의거래와 장애복구 검증 전에는 비권고 |

## 2. 인기 TradingView 스크립트에서 정확히 가져오는 것

TradingView 페이지의 인기 숫자는 `Boost`다. 아래는 2026-09-21 조회 당시의 대략적 스냅샷이며 계속 변한다. **Boost는 성과 지표가 아니다.** 공개 Pine 소스와 제작자 설명을 대조했으며, 스크립트가 제공하는 기능과 이 보고서가 새로 제안하는 기능을 구분했다.

| 원본 스크립트 | 원본에서 검증한 동작 | 이 전략에 가져올 부분 | 가져오지 않을 부분 / 별도 구현 |
|---|---|---|---|
| [Portfolio Simulator & Backtester](https://www.tradingview.com/script/kbaODuIz-Portfolio-Simulator-Backtester/) (약 75 Boost) | `indicator`이며 최대 5종목의 사용자 비중(합계 100%), None/Monthly/Quarterly/Yearly **무조건** 리밸런싱, 수수료, 정기 납입, 배당 재투자, TWR·낙폭 등 지표를 시뮬레이션한다. 배당은 `request.dividends`로 읽어 당일 종가 재투자한다. | SCHD/QQQM/IEF/IAUM을 25/25/30/20으로 넣어 **거래하지 않음 vs 무조건 분기 vs 무조건 연간**의 비교 기준선으로 쓴다. 배당·거래비용 가정을 명시한다. | 이 스크립트는 ±5%p 밴드가 없고 증권사 잔고·주문 API와 연결되지 않는다. 정기 납입은 원본에서 목표비중대로 분배하므로 ‘가장 저비중부터 매수’ 규칙은 원본 기능이 아니다. 세금·환전·스프레드·미체결을 포함한 실전 결과로 보지 않는다. |
| [Performance Metrics With Bracketed Rebalancing, BackQuant](https://www.tradingview.com/script/uTzHDFX6-Performance-Metrics-With-Bracketed-Rebalacing-BackQuant/) (약 76 Boost) | `indicator`이며 **3종목만** 다룬다. 목표비중은 33/33/34 고정이고, 기본 `Bracketed` 조건은 `max(현재 세 비중) > 40%`이다. 해당 조건에서 33/33/34로 되돌린다. `No Rebalancing`, `Daily`, `Bracketed`를 비교한다. | **임계값을 넘을 때만 거래해 회전율을 낮춘다는 발상**과 리밸런싱 방식 간 비교 관점만 참고한다. | 원본을 4 ETF·25/25/30/20·개별 목표 대비 ±5%p·분기 점검으로 설정할 수 **없다**. `max 비중 > 40%`는 ‘어느 자산이 목표에서 5%p 이탈’과 수학적으로 다르며 저비중 이탈도 직접 포착하지 않는다. 동일 정책 검증에는 새 4자산 계산기/백테스터가 필요하다. |

| [Dual Momentum Strategy](https://www.tradingview.com/script/wFRnnlQr/) (약 109 Boost) | 월 단위 상대·절대 모멘텀으로 위험자산/안전자산을 전환하는 별도의 전술 방식이다. | 현행 정책과 비교할 별도 모의 전략의 연구 주제로만 보관한다. | 4 ETF 목표비중에 덧씌우지 않는다. 자산군을 전환하면 현재의 정적 분산 투자정책이 바뀐다. |

**가장 중요한 정정:** 선행 보고서는 BackQuant 스크립트로 목표비중 25/25/30/20과 ±5%p를 ‘설정해 검증’할 수 있는 것처럼 표현했다. 공개 소스를 확인한 결과 **불가능하다**. 선행 보고서도 이 부분을 바로잡았다. 저비중 우선 납입 역시 Portfolio Simulator 원본에 들어 있지 않은 **제안 정책**이다. 이 소스 검토를 거쳐 ‘기존 스크립트 바로 연결’이 아니라 ‘독립적인 4자산 리밸런싱 엔진’이 필요한 것으로 설계 판단을 수정했다.

## 3. 자동매매에 반영할 정책안 — 원본과 구분한 새 규칙

다음은 위 TradingView 스크립트의 내장 전략이 아니라, **사용자의 4자산 목표와 선행 보고서 제안안을 실행 가능한 규칙으로 구체화한 설계 초안**이다. 실거래 전 사용자 승인이 필요하다.

1. **기준 자산·목표**: 티커가 확정되면 허용 목록을 네 ETF로 고정한다. 목표비중 `t = {SCHD:.25, QQQM:.25, IEF:.30, IAUM:.20}`. 레버리지·공매도·허용 목록 밖 주문 금지.
2. **평가 시각**: 미국 시장 3·6·9·12월의 마지막 *실제 거래일* 종료 후 보유수량·현금·배당·미체결 주문과 기준 가격을 읽는다. 미국 거래소 휴장·서머타임은 시장 캘린더로 처리한다. 종가에 계산한 주문을 같은 종가에 체결한 것처럼 가정하지 않는다.
3. **계산 통화·분모**: 해당 해외주식 계좌의 **USD 평가액**에서 `V = Σ(q_i × p_i) + 사용 가능한 USD 현금`으로 계산한다. 다른 보유자산이 있다면 이 전략의 별도 서브계정/장부 경계를 정해야 한다. KRW 잔액은 임의로 USD 주문 가능 현금에 넣지 않고, 환전 방식 확인 후 반영한다. 원화 성과는 별도 환율 시계열로 평가한다.
4. **트리거**: 분기 점검 시 현재비중 `w_i = q_i×p_i/V`에 대해 `max_i |w_i-t_i| ≥ 0.05`이면 주문안을 만든다. 5% **상대 비율**이 아니라 **5%포인트**다. 같은 분기 점검 이외의 매일 신호는 주문 트리거가 아니다. 밴드 안이면 주문하지 않는다.
5. **목표 차액**: 트리거되면 `d_i = t_i×V - q_i×p_i`를 산출하되, 확정된 외부 납입·수령 배당은 사용 가능한 USD 현금으로만 반영한다. 비용·가격·주문단위로 실제 수량을 보수적으로 낮춘다. 잔여 현금과 허용오차를 기록한다.
6. **실행 순서**: 이미 열려 있는 주문을 조회한다 → 동일 분기의 중복 실행을 막는다 → 매도 주문의 실제 체결·정산가능 현금 확인 → 매수 가능액으로 재계산 → 매수 주문 → 부분체결·거절·취소를 추적 → 다음 잔고 조회로 결과를 대사한다. 지정가·유효기간·미체결 취소 시간·최소 주문금액은 증권사와 사용자 조건을 정한 뒤 확정한다. 가격이 크게 변해 트리거가 사라지면 주문 전 재평가한다.
7. **추세 경보**: Chandelier를 선택한다면 주봉 확정 후 SCHD/QQQM의 `dir=-1` 여부만 감시한다. 둘 모두 약세인 상태가 되면 *정보 알림*을 보낸다. 분기 주문 규칙·목표비중을 자동 변경하지 않는다. SuperTrend는 비교 자료이며 동시에 실거래 신호로 쓰지 않는다.

예: 총 평가액 1억 2천만 원, 현재비중이 SCHD/QQQM/IEF/IAUM 순으로 `31/24/27/18%`라면 SCHD가 목표보다 6%p 높아 분기 트리거가 성립한다. 비용과 현금을 무시한 **이론적** 차액은 각각 `−720만/+120만/+360만/+240만 원 상당`이다. 이는 주문 수량이 아니며 가격·수수료·환율·체결 결과로 다시 산정한다. 원화 예시는 이해용으로, 실제 미국 ETF 주문 예산은 계좌의 USD 가용액 기준이다.

## 4. 구성과 실패 대응

```text
미국 거래일 캘린더·분기 일정 ─┐
증권사 잔고·현금·시세·미체결 ─┼─> 4자산 정책 엔진 ─> 위험 검사 ─> 승인/모의/실주문 게이트
확정된 목표비중·밴드·티커 ───┘                              │
                                                  체결 조회·잔고 대사·감사 기록

TradingView 주봉 Chandelier 알림 ─> 별도 검증·중복 제거 ─> 위험 점검 통지(주문 권한 없음)
TradingView Portfolio Simulator ─> 연구·정책 비교(계좌 원장 아님)
```

- **신뢰 경계**: TradingView 웹훅을 주문 명령으로 신뢰하지 않는다. 공식 문서에 따르면 웹훅은 외부 앱으로 HTTP POST를 보내지만 3초 초과 시 취소되고 도달 실패가 있을 수 있다. 웹훅을 사용할 경우 TLS, 인증, 타임스탬프·심볼·타임프레임 검증, 중복 제거, 재조회, 모니터링이 필요하다. 계정 비밀번호·증권사 API 키를 알림 본문에 넣지 않는다. TradingView는 웹훅 사용에 2단계 인증을 요구한다. [TradingView 웹훅 공식 안내](https://www.tradingview.com/support/solutions/43000529348-how-to-configure-webhook-alerts/)
- **알림 설정 변경**: TradingView 전략 알림은 생성 시 서버 측 사본을 사용하므로 차트의 설정 변경만으로 기존 알림이 갱신되지 않는다. 변경 시 기존 알림을 폐기하고 재생성·시험한다. [TradingView 전략 알림 공식 안내](https://www.tradingview.com/support/solutions/43000481368-strategy-alerts/)
- **주문 안전장치**: `DRY_RUN`을 기본값으로 하고 실주문은 별도 활성화·사용자 확인을 거친다. 허용 종목·계좌·총 주문액·건당 주문액·일일 주문 횟수·가용현금·최대 가격 괴리·주문 시간대를 제한한다. 계좌/API 오류, 오래된 시세, 서로 다른 잔고 응답, 환전 미완료, 휴장, 부분체결, 미체결이 발생하면 **추가 매수를 정지하고 경보**한다. 장애 후에는 주문 내역을 먼저 조회하고 재주문 여부를 결정한다.
- **운영 기록**: 계산에 사용한 시각·가격·환율·보유수량·배당·현금·버전·주문 ID·응답·체결·잔여 현금을 남긴다. 주문 재시도는 `계좌+정책버전+분기+티커+방향` 등의 실행 ID를 사용하되, **증권사 주문 ID와 체결 조회**로 실제 중복을 막는다. 비밀값·계좌번호 원문은 로그에 남기지 않는다.
- **실적 측정**: 백테스트에는 분배금의 지급/재투자 시차, 세금, 수수료, 스프레드, 환전비용, 거래일의 실제 체결 가능 가격을 반영한다. TradingView 지표 값과 원화 실계좌 수익률은 동일하지 않다.

분기 일정이 확정되어 있으므로 **핵심 주문을 TradingView 웹훅에 의존할 이유가 적다**. 웹훅 장애가 있더라도 분기 계산은 독립적으로 실행되고, TradingView는 별도 감시 역할을 해야 한다.

## 5. 검증·구현 착수 조건

### 단계별 검증

1. **정책 고정**: 실제 티커, 계좌 분리 범위, 밴드의 경계(`≥ 5%p`), 분기 시각, 신규 납입금 처리, 세금·환전 및 주문 허용량을 확정한다.
2. **4자산 독립 백테스트**: 원본 Portfolio Simulator의 `None`/`Quarterly`/`Yearly`와 독립 엔진의 같은 조건을 표본 대조한다. 이어 별도 ±5%p 결합 정책을 정확 상품 공통 기간 및 장기 프록시 구간에서 평가한다. 거래비용·USD/KRW·배당 가정을 분리한다. 인기 스크립트의 수익률이 나왔다고 정책 채택 근거로 삼지 않는다.
3. **단위·경계 시험**: 비중 차이 4.99%p/5.00%p, 현금 0/부족, 휴장·서머타임, 배당·액면분할, 주문 미체결·부분체결·거절, 가격 급변, 중복 실행, API 지연·오류, 환전 실패, 재시작 후 복구를 재현한다.
4. **읽기 전용 섀도 운영**: 실제 계좌 잔고로 주문안만 만들고 실제 수동 실행 결과와 대사한다. 최소 두 번의 분기 점검 주기와 밴드 초과를 모의 주입한 시험을 권고한다. 달력이 안 맞으면 과거 데이터 리플레이로 보완하되 실운영 검증을 대체하지 않는다.
5. **모의주문/소액 승인형**: 증권사가 해당 해외 ETF의 모의주문을 지원하는지 확인한 뒤 주문·취소·재조회 전 과정을 시험한다. 이후 사용자 승인형 실주문을 거쳐야 완전 자동화를 검토할 수 있다.

### 현재 확인이 필요한 입력

- `SHCD`가 `SCHD`인지, `AUM`이 `IAUM`인지 또는 다른 상품인지.
- 사용 중인 증권사·계좌 유형, 해외 ETF API 신청/권한, 모의투자 가능 범위, 주문·환전 방식.
- 실제 보유수량, USD/KRW 가용현금, 다른 자산이 같은 계좌에 있는지, 배당금 처리, 세금·수수료 조건.
- **분기+±5%p가 실제로 원하는 정책인지**, 임계값이 넘으면 네 자산 모두 목표로 복귀시킬지, 신규 납입금을 저비중 우선에 배분할지.
- 사용자 승인형 주문으로 시작할지, 검증 완료 후 완전 자동까지 목표로 할지.

## 6. 최종 권고

인기 스크립트의 장점을 **역할별로 제한적으로 채택**한다: Portfolio Simulator의 다중 ETF 기준 시뮬레이션, BackQuant의 ‘임계값 거래’ 발상, Chandelier의 확정 주봉 추세 **검토 알림**. SuperTrend의 롱·숏 가상 거래나 Dual Momentum의 자산 전환은 현재 정책에 편입하지 않는다. 실제 분기 리밸런싱은 별도의 4자산 정책 엔진이 증권사 잔고·체결 자료를 기준으로 계산한다.

기술적 가능성과 실계좌 운영 가능성은 다르다. 티커·증권사·계좌권한·위험한도와 검증 결과가 나오기 전에는 **자동 주문을 켜지 않는다**.
